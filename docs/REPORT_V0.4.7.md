## 1. ملخص التعديلات

تم في هذه المرحلة معالجة المشكلات الجوهرية المرتبطة باستقرار التطبيق وإدارة النماذج والمحادثات وحماية تجربة المستخدم دون تغيير المعمارية الأساسية (Flutter + SQLite + llama.cpp C++ FFI):

1. **إدارة غياب النموذج وحالاته**:
   - تمكين التمييز الواضح بين الحالات الخمس: `noModel` (لا يوجد نموذج)، `loading` (جارٍ التحميل)، `ready` (جاهز)، `generating` (جارٍ التوليد)، `error` (خطأ) عبر نوع مخصص `ChatUiState`.
   - تعطيل حقل الإدخال وزر الإرسال عند عدم وجود نموذج جاهز أو أثناء التحميل.
   - إظهار شريط/رسالة إرشادية عربية توضح للمستخدم عدم تثبيت نموذج مع زر مباشر للانتقال إلى شاشة الإعدادات واستيراد نموذج GGUF.
   - منع حفظ أي رسالة في قاعدة البيانات إذا تعذر تحميل النموذج أو لم يكن جاهزاً.
   - منع إرسال الرسائل المكررة عند النقر المتكرر السريع.
   - بقاء المحادثات السابقة قابلة للتصفح والقراءة بشكل كامل دون تأثر بغياب النموذج.

2. **حذف المحادثات وحماية البيانات**:
   - إضافة مربعات حوار تأكيد باللغة العربية قبل حذف أي محادثة فردية.
   - إضافة مربع حوار تأكيد مستقل باللغة العربية قبل مسح جميع المحادثات.
   - منع الحذف أثناء التوليد الجاري لحماية تناسق الذاكرة وقاعدة البيانات.
   - التحديث الفوري لقائمة المحادثات والواجهة عند الحذف.

3. **أسماء المحادثات**:
   - ضبط التسمية التلقائية بناءً على أول رسالة للمستخدم مع اقتطاع آمن عند 40 حرفاً.
   - وضع عنوان افتراضي بالعربية للمحادثات الجديدة الخالية من الرسائل ("محادثة جديدة").
   - حظر تغيير الاسم التلقائي الصحيح عند إرسال رسائل لاحقة.

4. **معالجة الأخطاء وحماية الموارد**:
   - تفريغ الموارد واستدعاء `_unloadLocked()` عند فشل تحميل النموذج لتحرير الذاكرة.
   - التعامل الآمن مع الأخطاء غير المتوقعة وتسجيل تشخيص محلي عبر `debugPrint` دون كتم الخطأ أو انهيار التطبيق.
   - حماية استدعاءات `notifyListeners()` بعد التخلص من الكائن (`dispose`).
